# Muse Invite Hub — violet exchange, 2026-09-29

## Direction

Make the purpose immediately legible: free Muse invite codes, copied here and redeemed in Muse for community-reported token rewards. Keep actual codes in the first viewport. Add a recognizable identity through expressive type, lilac paper surfaces and perforated code slips; the functional list itself carries the design.

## Visual tokens

- Ink: #29223b; secondary: #6f6683.
- Violet: #6941e0; deep violet: #4e28b7.
- Paper: #fffefd; canvas: #f7f4ff; subtle lilac line: #e1d8f4.
- Small mint acknowledgement: #e6f5dd, used for “free / no sign-in” and successful copy only, never false availability.
- Display: locally hosted Bricolage Grotesque Variable; body: local Manrope; full codes: system monospace.

## Layout

A compact navigation line leads into a two-line introduction at most. The exact-intent H1 and plain-language benefit explain the site. The wide left column is a stack of white code slips, each with full code and direct copy. A perforation visually separates content from its action. The right column visualizes the two-sided token reward, then gives three short redemption steps. Mobile puts code slips before the explanatory panel.

Avoid: a full-height hero, decorative illustration before codes, a product-card/catalog grid, hidden codes, account gates, arbitrary fake stats, and scroll/3D effects that delay the action. Keep five provided codes visible and selectable; use restrained hover and copied-state feedback, honoring reduced motion.

## Critique before implementation

The prior grey table solved hierarchy but lacked a visual identity. This revision spends its visual emphasis on the code list itself, with a smaller complementary reward diagram. The diagram explains why both sides share; it must not push the list below the fold. No pricing, cart-like tiles, giant promotional artwork or random animated decoration.
